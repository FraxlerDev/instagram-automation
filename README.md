# Fraxler Insta Automation

Локальна українська вебпанель та Instagram-бот для професійного акаунта на офіційному Instagram API.

Сценарій:

1. Коментар під дозволеною публікацією містить слово «гайд».
2. Бот публічно відповідає і надсилає одну private reply в Direct.
3. Коли людина відповідає «ГОТОВО», бот надсилає посилання на вибраний файл.
4. Подальший діалог бот не автоматизує.

## 1. Локальне налаштування

```bash
cd /absolute/path/to/instagram-automation
cp .env.example .env
nano .env
```

Вставте токен у `INSTAGRAM_ACCESS_TOKEN`. Секрет із **Instagram > API setup with Instagram login** вставте у `INSTAGRAM_APP_SECRET`. Не публікуйте `.env`.

Згенеруйте випадковий verify token:

```bash
python3 scripts/rotate_verify_token.py
```

Команда безпечно збереже результат у `WEBHOOK_VERIFY_TOKEN` файлу `.env`, не друкуючи його.

Перевірте токен і дізнайтеся Instagram Account ID:

```bash
python3 scripts/check_token.py
```

Скопіюйте `id` у `INSTAGRAM_ACCOUNT_ID` файлу `.env`.

Покажіть останні 25 публікацій та їхні Media ID:

```bash
python3 scripts/list_media.py
```

## 2. Запуск

```bash
python3 -m bot.server
```

В іншому терміналі:

```bash
curl http://127.0.0.1:8794/health
cloudflared tunnel --config ~/.cloudflared/config.yml run instagram-guide-bot
```

Постійна адреса тунелю, наприклад `https://bot.example.com`, має бути записана у `PUBLIC_BASE_URL`.

## 3. Webhooks у Meta

У **Instagram > API setup with Instagram login > Configure webhooks**:

- Callback URL: `<PUBLIC_BASE_URL>/webhook`
- Privacy Policy URL: `<PUBLIC_BASE_URL>/privacy`
- User Data Deletion URL: `<PUBLIC_BASE_URL>/data-deletion`
- Verify token: точне значення `WEBHOOK_VERIFY_TOKEN`
- події: `comments` і `messages`

Після збереження підпишіть професійний Instagram-акаунт на вебхук, якщо Meta показує окрему кнопку для цього.

## Автозапуск через systemd

Шаблони unit-файлів знаходяться в каталозі `systemd/`. Створіть із них користувацькі служби, підставивши поточний каталог проєкту:

```bash
mkdir -p ~/.config/systemd/user
PROJECT_DIR="$PWD"
sed "s|__PROJECT_DIR__|$PROJECT_DIR|g" systemd/instagram-guide-bot.service.example \
  > ~/.config/systemd/user/instagram-guide-bot.service
sed -e "s|__PROJECT_DIR__|$PROJECT_DIR|g" \
    -e "s|__CLOUDFLARED_CONFIG__|$HOME/.cloudflared/config.yml|g" \
    systemd/instagram-guide-tunnel.service.example \
  > ~/.config/systemd/user/instagram-guide-tunnel.service
systemctl --user daemon-reload
systemctl --user enable --now instagram-guide-bot.service instagram-guide-tunnel.service
```

Перевірка стану та журналів:

```bash
systemctl --user status instagram-guide-bot.service instagram-guide-tunnel.service
journalctl --user -u instagram-guide-bot.service -u instagram-guide-tunnel.service -f
```

## 4. Графічна панель

За замовчуванням панель доступна лише на цьому ноутбуці:

```text
http://127.0.0.1:8795/admin/
```

Для доступу з телефона в домашній мережі в `.env` можна дозволити лише свою підмережу:

```text
ADMIN_HOST=0.0.0.0
ADMIN_PORT=8795
ADMIN_ALLOWED_NETWORKS=127.0.0.0/8,192.168.0.0/24
```

Після перезапуску служби відкрийте на телефоні `http://<LAN_IP>:8795/admin/`, підставивши локальну IP-адресу ноутбука. Телефон і ноутбук мають бути підключені до однієї Wi‑Fi мережі. Не відкривайте порт `8795` у роутері й не додавайте цю панель до публічного Cloudflare Tunnel.

Під час першого відкриття створіть локальний пароль довжиною щонайменше 10 символів. У панелі можна:

- підключати кілька професійних Instagram-акаунтів через офіційний Instagram OAuth;
- зберігати токени підключених акаунтів у SQLite в зашифрованому вигляді;
- призначати окремий Instagram-акаунт кожній автоматизації та перевіряти його API/webhook-підписку;
- створювати окремі автоматизації для різних публікацій;
- вибирати публікацію зі списку Instagram або вставляти її посилання;
- редагувати ключові слова та всі три тексти відповіді;
- завантажувати файли поширених форматів до 100 МБ;
- вибирати файл зі спільної бібліотеки та повторно використовувати його для різних Instagram-акаунтів;
- зберігати нові файли під латинськими назвами, автоматично транслітеруючи кирилицю;
- створювати папки й підпапки та безпечно переміщувати між ними активні файли;
- дублювати сценарій як вимкнену копію для швидкого налаштування;
- перевіряти файл, публікацію, API, конфлікти ключових слів і тунель;
- вмикати, вимикати, архівувати, відновлювати та видаляти автоматизації;
- переглядати історію коментарів і статуси трьох етапів: відповідь, Direct, файл;
- бачити загальну аналітику та конверсію для кожного сценарію;
- створювати й завантажувати резервні ZIP-копії бази та всієї бібліотеки;
- автоматично повторювати невдалі відповіді Meta до 8 разів і вручну запускати повтор із центру помилок;
- контролювати Instagram API, публічну адресу webhook, служби та час останньої події;
- отримувати опціональні Telegram-сповіщення про збій і відновлення;
- переглядати користувачів, Direct-повідомлення, мітки та внутрішні нотатки;
- передавати діалог людині й відповідати в Instagram Direct із панелі;
- видаляти дані конкретного користувача та автоматично очищати стару історію;
- зберігати чернетки, переглядати версії та відновлювати попередню конфігурацію;
- будувати багатокрокові сценарії та розгалуження за відповідями користувача;
- вмикати перевірку фактичної підписки перед видачею файлу і бачити її статус у картці користувача;
- зберігати й показувати в діалозі вкладення з Instagram Direct: зображення, відео, аудіо та поширені матеріали;
- перемикати темну та світлу тему панелі;
- отримувати короткі спливаючі підтвердження дій у правому нижньому куті;
- переглядати стан і перезапускати служби.

### Кілька Instagram-акаунтів

Відкрийте **Instagram-акаунти**. Скопіюйте показаний **OAuth Redirect URI** і додайте його в Meta у налаштуваннях Instagram Business Login як дозволену адресу перенаправлення. Введіть у панелі цифровий **Instagram App ID (Client ID)** та натисніть **Підключити Instagram-акаунт**. Авторизація відбувається на сторінці Instagram; пароль Instagram не проходить через локальну панель.

Після повернення Instagram панель зберігає довготривалий токен у зашифрованому вигляді й намагається підписати акаунт на події `comments` і `messages`. Кнопка **Перевірити API** повторно перевіряє токен, профіль і webhook-підписку. У редакторі кожної автоматизації з’явився вибір акаунта.

Початковий акаунт із `.env` переноситься автоматично як основний. Відключення такого акаунта видаляє його копію токена з бази, але значення в `.env` потрібно прибрати окремо, якщо ви хочете повністю видалити секрет із диска.

Зміни сценаріїв читаються з SQLite одразу й не потребують перезапуску. Початкові значення з `.env` використовуються лише для автоматичного перенесення першого сценарію в порожню базу.

Автоматична резервна копія створюється один раз на день, навіть якщо служба працює безперервно. Зберігаються останні 14 автоматичних копій. Ручні копії не видаляються автоматично.

У розділі **Бібліотека** можна завантажувати JPG/JPEG, PNG, WEBP, MP4, MOV, PDF, DOCX, XLSX, PPTX, TXT, MP3, WAV і ZIP (до 100 МБ), а також створити вкладений шлях, наприклад `Курси/Читання`; на диску він буде збережений як `kursy/chytannia`. Для JPG/JPEG, PNG і WEBP картка показує візуальне прев’ю; натискання відкриває повне зображення. Назва `Новий гайд.pdf` перетворюється на `novyi-haid.pdf`. Якщо такий файл уже існує, програма додає номер (`novyi-haid-2.pdf`). Бібліотека є спільною: картка показує Instagram-акаунти, чиї автоматизації використовують файл, а фільтр відбирає файли конкретного акаунта. Переміщення документа через панель автоматично оновлює всі пов’язані автоматизації.

### Telegram-сповіщення

Відкрийте **Налаштування**, введіть токен власного Telegram-бота та Chat ID, увімкніть сповіщення й натисніть **Надіслати тест у Telegram**. Токен зберігається тільки в локальній SQLite-базі з файловими правами `600`; не передавайте його іншим людям. Статуси мають зрозумілі позначки: 🟢 запуск, ✅ схема працює або повністю відновлена, 🟠 частковий збій, 🔴 схема не працює, ⚫ нормальна зупинка.

Telegram надсилає рівно одне повідомлення про кожен коментар під публікацією з активною автоматизацією. Воно містить Instagram-акаунт, посилання або Media ID публікації, автора та текст коментаря. Якщо ключове слово збіглося, додаються назва автоматизації й текст автоматичної відповіді. Без збігу показується рядок `🎯 Збіг сценарію: ні — автоматична відповідь не запускається`, і Instagram-бот не відповідає. Повторна доставка того самого webhook не створює дубль.

Власні відповіді підключеного Instagram-акаунта, зокрема налаштований текст `Написав вам у Direct 😊`, ігноруються. Вони не запускають сценарій повторно й не створюють окреме Telegram-повідомлення.

Коли користувацька служба запускається, вона чекає 15 секунд на готовність мережі та надсилає **«Fraxler Insta Automation запускається»**. Якщо Telegram ще недоступний, виконується до 6 повторів. Під час нормальної зупинки або перезапуску systemd надсилає **«Служба зупиняється»**. При раптовому зникненні живлення повідомлення про зупинку неможливе, оскільки ноутбук уже не має змоги звернутися до Telegram.

### Ручні діалоги

У розділі **Користувачі** можна відфільтрувати людей за Instagram-акаунтом. Кожна картка й діалог показують акаунт, через який відбувається спілкування; ручна відповідь, нотатки, перевірка підписки та видалення даних зберігають цей контекст. Надсилання ручної відповіді автоматично вмикає ручний режим, щоб бот не відповів паралельно. Instagram API може відхилити повідомлення, якщо воно не дозволене для поточного стану діалогу; така помилка буде показана в картці.

### Аналітика підписників

Сторінка **Аналітика** показує для кожного підключеного Instagram-акаунта поточну кількість підписників, нових і втрачених за день та чистий приріст. Дані оновлюються після запуску, потім раз на 30 хвилин, а також вручну кнопкою **Оновити показники**. Якщо Instagram не повертає денне розділення для акаунта, панель залишає ці значення порожніми й не підміняє їх припущеннями.

Для кожної автоматизації окремо зберігаються підтверджені підписки. Конверсія зараховується тільки тоді, коли User Profile API після початкового Direct підтвердив відсутність підписки, а після наступної дії користувача — її наявність. Тому цей показник консервативний: він не включає давніх підписників та випадки, коли Instagram не повернув статус.

### Багатокрокові сценарії та підписка

У редакторі автоматизації блок **Багатокрокові правила** працює як проста машина станів. Початковий стан після коментаря — `waiting`. Правило задає поточний стан, ключові слова відповіді, текст наступного повідомлення та наступний стан. Декілька правил з однаковим поточним станом утворюють розгалуження. В останньому правилі можна позначити **Надіслати файл і завершити**.

Опція **Перевіряти через Instagram User Profile API** перевіряє поле підписки безпосередньо перед надсиланням файлу. Якщо Instagram не підтвердив підписку, бот надсилає налаштоване нагадування; користувач може підписатися й повторити відповідь. У картці користувача є останній збережений статус та кнопка **Перевірити зараз**.

### Зберігання даних

Типовий строк зберігання журналів — 90 днів, мінімальний — 7. Його можна змінити в **Налаштуваннях**. Очищення виконується автоматично раз на день і одразу після зміни строку. Дані окремого користувача можна безповоротно видалити в його картці.

## Безпека і повтори

- Meta webhook-підпис перевіряється через HMAC SHA-256.
- SQLite пам'ятає оброблені коментарі та повідомлення, щоб не дублювати відповіді.
- Панель захищена паролем і списком дозволених локальних IP-мереж та не публікується через Cloudflare Tunnel.
- Пароль зберігається як PBKDF2-хеш, сесії мають CSRF-захист.
- Після видачі файлу бот більше не відповідає цьому користувачу автоматично.
